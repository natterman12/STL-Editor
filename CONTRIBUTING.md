# Contributing to STL Editor

Thanks for helping. Bug reports, model files that break things, ideas and pull requests are all welcome.

## Reporting a problem

Use **[New issue › Bug report](https://github.com/natterman12/STL-Editor/issues/new/choose)**. The form asks for the steps, the version and, most usefully, the model file. Mesh bugs are almost always about one particular file, so a report with the STL usually gets fixed fastest.

## Setting up

You need Windows 10/11 and Python 3.12 or newer.

```powershell
git clone https://github.com/natterman12/STL-Editor.git
cd STL-Editor
pip install -r requirements.txt pytest
python main.py            # desktop window
python main.py --browser  # the same UI in your browser, handy with dev tools
python -m pytest -q tests
```

The web edition's engine tests need [Node.js](https://nodejs.org) 20 or newer
(`node --test tests/web_engine.test.mjs`; `pytest` runs them too when Node is installed).
To try the web edition locally, serve the `web` folder and open it with `?web`:

```powershell
node tests/ui/serve.js web 8000   # then open http://127.0.0.1:8000/?web
```

(Python's `http.server` works too where it sends `.js` files as JavaScript; on many Windows
machines it doesn't, and the page then stays blank.)

The UI tests (Playwright) are in `tests/ui`; see its README.

## Where things live

| Path | What it is |
|---|---|
| `stleditor/features.py` | Every tool, as a function `f_<name>(state, fid, params, result, ctx)`, plus the `EVALUATORS` table |
| `stleditor/feature_modules/` | Features in their own file (one per feature, registered on import through `registry.py`); the web side is `web/engine/feature_modules/` with the same file names |
| `stleditor/document.py` | The timeline: adding / editing / reordering features, cached re-evaluation, undo, `.stlx` files |
| `stleditor/geometry.py` | Mesh I/O, repair, voxel rebuild, hollow, plane frames |
| `stleditor/printing.py` | Fit to bed, connectors, threads, lay flat, sculpt, remesh |
| `stleditor/sketch.py` | Sketch entities → 2D regions |
| `stleditor/server.py` | The local JSON API the UI talks to (`/api/...`) |
| `web/js/tools.js` | The panel for each tool: fields, defaults, hints |
| `web/js/app.js` | Toolbar, browser tree, timeline, menus |
| `web/js/sketcher.js`, `constraints.js` | Sketch mode and the constraint solver |
| `web/js/viewer.js` | three.js viewport |
| `web/js/api.js` | Talks to the engine: HTTP in the desktop app, the Web Worker in the web edition (plus the web edition's files, recent list and autosave) |
| `web/js/webstore.js` | The web edition's browser storage (IndexedDB): autosave copies, recent files, added fonts |
| `web/sw.js`, `web/manifest.webmanifest` | Offline copy and app install for the web edition. `build_web.py` writes the file list and version hash into `sw.js` (a test checks it) |
| `web/engine/` | The web edition's engine, a JavaScript port of `stleditor/` (`features.js`, `document.js`, `sketch2d.js`, `printing.js`, `meshtools.js`, `io.js`, `routes.js`) running in `worker.js`; `voxel.js` (Hollow, Repair › Rebuild), `meshedit.js` (Sculpt, Remesh) and `decimate.js` (Simplify, a port of the quadric decimation the desktop uses) hold the voxel and mesh tools |
| `web/vendor/manifold/` | manifold-3d WebAssembly build used by the web engine |
| `docs/app/` | Published copy of `web/` for GitHub Pages: generated by `python packaging/build_web.py`, don't edit by hand |

**Adding a tool** usually means:

1. Write an `f_<name>` evaluator and register it in `EVALUATORS` and `LABELS`.
2. Add a panel definition in `web/js/tools.js`.
3. Add a button in `ribbonDef()` in `web/js/app.js`. Tool search picks it up automatically.
4. Add a test in `tests/test_engine.py` that checks a volume or a bounding box you can work out by hand.
5. Port the evaluator to `web/engine/features.js` (or add its type to `DESKTOP_ONLY_TYPES` and to `DESKTOP_TOOLS` in `app.js`), with a matching test in `tests/web_engine.test.mjs`.
6. Run `python packaging/build_web.py` so the website's copy is current.

## How to add a feature

A new feature gets its own file pair, so nothing in the shared files changes except one import line:

1. Create `stleditor/feature_modules/<name>.py` with `f_<name>` and end it with `register('<name>', f_<name>, '<Label>')`.
2. Create `web/engine/feature_modules/<name>.js` with the same name, `f_<name>`, and `register('<name>', f_<name>, '<Label>')`.
3. Add `from .feature_modules import <name>` at the bottom of `stleditor/features.py`, and `import './feature_modules/<name>.js';` at the top of `web/engine/features.js`.
4. Continue with steps 2–6 of **Adding a tool** above (panel, ribbon button, tests, `build_web.py`).

Helpers that a feature file shares with others (`apply_tool`, `_float`, `applyTool`, `place`) are imported by name from `features`; the feature module must not import `features` as a whole.

## Guidelines

- The engine always works in **millimetres**. Inch mode only changes what the UI shows.
- Feature evaluators must be **deterministic**. They're re-run whenever an earlier step changes.
- Raise `GeometryError("plain-English message")` for anything the user can fix. The message is shown in the app as-is.
- Keep the UI free of build steps: plain ES modules, no bundler.
- Run `python -m pytest -q tests` before opening a pull request. GitHub runs the tests on every pull request.

## Support Fins

`web/vendor/support-fins/` is [Support Fins](https://github.com/gittrahan/support-fins)' own
plugin engine, bundled unmodified by `python packaging/update_support_fins.py [vX.Y.Z]` (needs
git and Node; esbuild is fetched with npx). The web edition imports `engine.esm.js`
(`web/engine/supportfins.js`); the desktop app runs `engine.iife.js` in mini-racer
(`stleditor/supportfins.py`). The tool panels are built from the engine's options schema, so
don't hard-code its settings. The script also builds extras for what their site has and the plugin entry doesn't offer
yet (`packaging/support_fins_extras/`): curved walls (made from their `draw_entry.js`),
gussets (`web/gusset.js`), anchor fins (`web/sway.js`) and Suggest / Strength
(`web/orient.js`). Each extra is built and tried on a test part on its own; one that a new
release breaks is left out (`VERSION.json` `features` / `extras`) and the app falls back (a
curve as short straight walls) or hides that tool. The **Support Fins update** workflow runs the script daily and,
when the tests pass, pushes the new engine; installed desktop apps then download it from the
Pages site (checked against `VERSION.json`'s SHA-256). A release that changes the integration
contract (`API` in the script) is refused until this app is updated for it.

## Releasing (maintainer)

1. Bump `__version__` in `stleditor/__init__.py` and `VERSION` in `web/engine/routes.js` (a test checks they match), and run `python packaging/build_web.py`. Optionally add `.github/release-notes/v<version>.md`.
2. Commit, then tag and push: `git tag v1.2.1 && git push && git push --tags`.
3. The **Release** workflow tests, builds and smoke-tests the portable zip and publishes it as `STL-Editor-Windows-portable.zip`. Installed copies see the update within a day. The web edition updates as soon as `docs/app` is pushed to `main`.
